# 平台端到端工作流

所有子 skill 统一遵循此流程。入口 `creator-platform` 路由到子 skill 后，子 skill 按此执行。

## 阶段 0：读配置

1. 读 `config/creator.yaml`（安装目录优先，仓库内为模板）。缺文件时用默认值并提示用户。
2. 确认引擎路径：`config.engine_root` → `~/.codex/skills/wechat-silicon-editor`。缺失则交 `content-engine` 安装。

## 阶段 1：接素材 + 创作指令

按 `references/brief.md` 的指令卡收集。必须拿到/推断出：

- **素材**：URL / 文本 / 截图 / PDF / 仓库 / 主题（至少一项）
- **角度与立场**：用户对这件事的判断（这是文章的灵魂，优先于一切模板）
- **语气与长度**：relaxed / editorial / technical / market；短 / 中 / 长
- **平台清单**：缺省用 `config.default_platforms`
- **标题方向**：用户给就按用户；没给最后再拟
- **配图与 CTA**：配图来源偏好、行动号召

指令缺项：能合理推断就补齐（用 config 口径）；关键分歧（角度、平台、是否双语）先问用户一句，不要猜。

## 阶段 2：事实层（新闻类必做）

1. 抓取/读取素材原文；把"事实 / 来源声称 / 我的推断"三者分开标注。
2. 核查关键数字、日期、人名、引语（多来源交叉，详见 `skills/news-to-content/references/fact-check.md`）。
3. 无法核实的写"据 X 报道""未经证实"，禁止编造引语、数字、截图。
4. 配图计划：先定图片角色（封面/原始材料/结构性证据），再去截图。

## 阶段 3：母稿（公众号长文）

1. 先写一句私有论点句：`这篇文章要论证______，因为______。`
2. 建一条论证主线（事件 → 张力 → 机制 → 对谁的影响 → 更大判断），不硬套编号小标题。
3. 按 `references/editorial-guide.md` 写作：第一人称观察、长短句交替、具体名词、去 AI 味。
4. 标题最后拟（`references/editorial-guide.md` 第 6 节）。
5. 图片按阅读顺序命名 `01_`、`02_`，紧跟 `图 01｜… 图片来源：…`。

## 阶段 4：多平台改编

1. 从母稿提取"事实对等清单"：论点、痛点、完整流程、限制、安全/信任机制、数据生命周期、诚实局限、技术栈、链接。
2. 逐平台按 `references/platforms.md` 改编：换钩子、换长度、换证据、换 CTA。**禁止跨平台粘贴同一段文案。**
3. 中英双语项目：每个平台产出 `-zh`/`-en` 两版，配图语言匹配。

## 阶段 5：构建（交 content-engine）

1. 用 `wechat-silicon-editor` 脚本构建公众号 HTML/ZIP（`--strict-editorial`）、各平台发布页（`build_channel_page.py`）、X 组件（`build_x_post.py`）。
2. 严格校验：单一 h1、图片编号连续且有来源图注、行内样式、复制按钮嵌入全部本地图、无横向溢出、无蓝色组件色、工具栏不出现在复制正文里。

## 阶段 6：交付与存档

1. 归档到 `config.archive_root/<slug>/`：`<slug>.md`、`<slug>.html`、`images/`、`social/`（X 组件）、`platforms/`（各平台 md/html）。
2. 交付清单：Markdown 源稿、HTML 预览、图片目录、ZIP、各平台发布页。
3. 告诉用户：打开每个 HTML → 用复制按钮 → 人工审阅 → 在对应平台完成最终发布（除用户明确授权外，不代为发布）。
4. 若配置了存档 git 仓库，按需提交；只提交本次文章目录与 skill 变更，不夹带无关文件。

## 修订规则

标题/论点/事实任何一处改动后，必须**重建所有产物**（md/html/images/platforms）再交付，保持同一修订版本；后续修改更新同一文章目录，不另开重复目录。
