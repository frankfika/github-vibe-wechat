# 平台适配规则与校验清单

构建阶段由 `content-engine`（`wechat-silicon-editor` 脚本）产出 HTML；本文件决定**每篇文案怎么写**，以及交付前**校验什么**。

## 适配总则

1. 从母稿提取"事实对等清单"：论点、痛点、完整工作流、限制、安全/信任机制、数据生命周期、可选控制、诚实局限、技术栈、链接。每个长文平台必须保留同等事实深度，除非平台结构上不允许。
2. 平台原生 ≠ 把文章改成功能清单。换钩子、换长度、换证据、换 CTA，**禁止跨平台复制同一段文案**。
3. 中英双语：成对产出 `-zh`/`-en`，URL/产品名/协议名/数值限制两版一致；配图语言匹配。
4. 最终发布是外部副作用：准备并打开平台编辑器，由用户审阅后执行最终发布；除非用户明确授权，不代为发帖。

## 各平台要点

| 平台 | 形态 | 钩子 | 事实深度 | 复制模式 | 其他要求 |
|---|---|---|---|---|---|
| **公众号** | 母稿长文 | 痛点和结果，不报技术栈 | 全量 | rich | 单一 h1；图片编号+来源图注；复制按钮嵌入全部本地图 |
| **X/Twitter** | 短帖 + 可选长文 + 16:9 配图 | 读者痛点/惊讶/结果 | 精简 | plain（短帖） | ≤240 中文字符含 URL；不承诺一次粘贴同时插入图文（先 intent 预填文字，再单独粘贴图） |
| **Reddit** | 第一人称透明帖 | 原始痛点、为何现有方案不对 | 中 | markdown | 选一个主题匹配的子版块；读其规则与自我推广政策；披露作者身份；不要求点赞；不跨社区复制 |
| **Hacker News** | `Show HN:` 文本帖 | 直接可运行的产品 URL | 技术/个人说明 | plain | 作者需在场讨论；正文优先，截图复制/下载作为可选上下文；不要求投票 |
| **知乎** | 中文长文回答/文章 | 用户问题 + 产品判断 | 全量 | rich | 围绕问题、实现选择、局限、实际用法 |
| **CSDN** | 技术中文文章 | 问题 → 架构 → 安全模型 → 部署 → 用法 → 局限 → 源码 | 全量技术 | markdown | 保持 Markdown 友好结构 |
| **Product Hunt** | 发布工作表 + Maker Comment | 产品名、标语、描述、Topics | 字段化 | plain | 提交前核对当前字段要求；不虚构画廊素材 |
| **B站** | 视频/专栏发布包 | 标题、简介、口播提纲、置顶评论、标签 | 中 | markdown | 不伪装成自动上传视频；用户手动上传 |
| **小红书** | 图文笔记发布包 | 短标题、图先文后、互动问题 | 精简 | markdown | 5–8 个相关标签；避免"爆款""永久安全"类不可验证承诺 |

复制模式：`rich`=富文本（知乎）、`markdown`（Reddit/CSDN/B站/小红书）、`plain`（HN/Product Hunt/X）。每个发布页提供分字段复制、正文复制、copy-all 兜底、官方编辑器链接；有图处提供图片复制/下载。

## 交付前校验清单

- [ ] 产品名、live URL、仓库 URL、许可证、截图四处一致（项目类）
- [ ] 事实层：数字/日期/人名/引语可溯源；事实、来源声称、推断三态标注（新闻类）
- [ ] 所有本地图片存在、从 `01_` 连续编号、有 `图 N｜… 图片来源：…` 图注
- [ ] rich 复制载荷嵌入了文章用到的全部本地图片
- [ ] 每个复制/下载/打开编辑器按钮在 `file://` 下可用；图片下载用 Blob/object-URL 处理器
- [ ] 无任何平台收到从另一平台原样粘贴的文案
- [ ] 双语项目：相关渠道都有 `-zh`/`-en` 页面，且事实与配图语言匹配
- [ ] 无未经验证的"爆款""永久安全""开源""生产可用"等措辞
- [ ] 存档目录与当前修订一致（改标题后已重建全部产物）
